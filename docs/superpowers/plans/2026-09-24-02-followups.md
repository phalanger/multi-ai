# 02 计划遗留事项（供后续计划引用）

来源：02-probe 执行过程中各任务审查、最终审查与修复复审的裁决。
写 03-core、04-app 计划时必须逐条处理本文件。

## 验证记录

- **V1 已完成（2026-09-24）**：在 macOS（zellij 0.45.1，Rust 1.98）上
  全量 100 个测试通过（含两个 `#[cfg(unix)]` install 测试），clippy 无警告。
  同时发现并修复一个依赖宿主环境的测试：`/opt/homebrew/bin` 已装 zellij
  时查找顺序测试失败；已拆出 `find_zellij_in` 与 `default_dirs`。
- **V2 未能确认**：`ZELLIJ_SOCKET_DIR=<空目录>` 下 `list-sessions -n`
  仍列出缓存中可恢复的 session（`(EXITED - attach to resurrect)`，退出码 0），
  无法造出“零 session”。探针继续以输出文本 `No active zellij sessions`
  判断，不依赖退出码；可恢复的 session 被解析为 `exited: true`，不轮询其 pane。

## 03-core 必须处理

- **C1 zellij 命令超时与报错节流**：`zellij action` 挂起会卡住整个
  serve 循环；同一 session/pane 的持续错误每个周期重复上报。
  为子进程加超时，并按（错误码，session/pane）每次故障只报一次。
- **C2 spool 定期清理**：目前只在 serve 启动时清理超过 7 天的文件；
  长时间运行的 serve 应每天清理一次。
- **C3 hook 与 serve 的数据目录一致**：hook 在 agent 的交互环境中运行，
  serve 在 SSH exec 环境中运行；只有一方设置 `MAI_HOME` 时，
  事件会写到 serve 读不到的地方。考虑把数据目录写进 hook 命令。
- **C4 serve 单实例**：半开的 SSH 连接可能留下旧 serve；
  Windows 上还会锁住 `mai-probe.exe` 导致无法重新部署。
  需要单实例保护；`ack.tmp`、`<config>.mai-tmp` 固定文件名也在此处理。
- **C5 install-hooks 串行化**：部署时每台主机的 install-hooks 串行执行。
- **C6 UTC 零点跨天**：记录按自身 `ts_ms` 归档到天文件，
  跨零点的极小时间窗口内可能被跳过；读取时可回看前一天文件的尾部。
- **C7 Windows 本机启动探针的控制台窗口**：用 `CREATE_NO_WINDOW`。
- **C8 构建哈希**：部署比对需要的版本构建哈希。

## 04-app 必须处理（或在 03 顺带处理）

- **S1 hook `Exited` 后被抓屏重新绑定**：agent 退出后，残留的
  标题（`Claude Code`）或最后一屏会让下一轮抓屏重新识别该 pane，
  随后产生一次虚假的 `Done` 提醒。建议：hook `Exited` 之后，
  至少出现一次“识别失败”才允许抓屏重新绑定。
- **S2 仅抓屏识别的 agent 短暂失配**：Claude 在默认权限模式或部分
  弹窗（如 AskUserQuestion、计划确认）下屏幕特征都不匹配时，
  会被报告为 `Exited` 再重新识别，期间的 `NeedsInput` 会丢失。
  建议：只要该 agent 自己的任一规则（标题、命令、屏幕、
  needs-input、done）仍匹配就保留绑定，或连续两次失配才判定退出。
- **S3 `paste -p` 实测**：`SendText` 只核对了 `--help` 参数形式，
  在界面联调时实测。
- **S4 设计文档 4.5 措辞**：显式 `--zellij` 路径不存在时不再回退到
  PATH 或登录 shell，文档中的回退链需注明这一点。
